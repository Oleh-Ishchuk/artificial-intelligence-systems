# Генератор commit-повідомлень

Застосунок читає `git diff --staged` і за допомогою локальної моделі пише commit-повідомлення у форматі Conventional Commits (`type(scope): опис`). Повідомлення друкується в терміналі в міру генерації.

## Встановлення

1. Встановіть [Ollama](https://ollama.com), [git](https://git-scm.com), Python 3.10+ і пакет `openai`:
   ```
   pip install openai
   ```
2. Завантажте модель:
   ```
   ollama pull qwen3:4b-instruct-2507-q4_K_M
   ```
3. Переконайтесь, що Ollama запущений (на Windows він зʼявляється в треї). Перевірка: команда `ollama list` показує завантажену модель.

## Швидка перевірка

Скрипт читає зміни, додані командою `git add`, тож для запуску потрібен репозиторій із такою зміною. Створіть тимчасовий репозиторій і запустіть скрипт із теки `app` (де лежить `commit_msg.py`).

Windows (PowerShell):
```
$script = (Resolve-Path commit_msg.py).Path
New-Item -ItemType Directory -Force $env:TEMP\demo-repo
cd $env:TEMP\demo-repo
git init
python -c "open('calc.py','w').write('def add(a, b):\n    return a + b\n')"
git add calc.py
python $script
```

Linux / macOS (bash):
```
script=$(realpath commit_msg.py)
mkdir -p /tmp/demo-repo && cd /tmp/demo-repo
git init
python -c "open('calc.py','w').write('def add(a, b):\n    return a + b\n')"
git add calc.py
python "$script"
```

Очікуваний результат: одне повідомлення в потоковому виводі. Точне формулювання може відрізнятись, головне, що це один рядок у форматі Conventional Commits.

## Використання у власному репозиторії

Додайте зміни командою `git add` і запустіть скрипт:

```
git add <файли>
python <шлях до>/commit_msg.py
```

Скрипт візьме `git diff --staged`, тобто лише додані зміни. Якщо нічого не додано, він повідомить: «Немає змін».

### Diff із файлу

Замість `git diff --staged` можна передати готовий diff із текстового файлу параметром `--file`. Файл створює сам git:

```
git diff --staged --output=diff.txt
python commit_msg.py --file diff.txt
```

Параметр `--output` зберігає файл у UTF-8 в будь-якій оболонці. У Windows PowerShell 5.1 запис `git diff > diff.txt` дає UTF-16, який скрипт не прочитає.

### Інші параметри

`--base-url`, `--model` і `--timeout` дозволяють вказати інший сервер, модель і таймаут. За замовчуванням використовується Ollama на `http://localhost:11434/v1`.

## Приклад

Зміна в репозиторії: нова функція в `calc.py`.

```
$ git diff --staged
diff --git a/calc.py b/calc.py
new file mode 100644
--- /dev/null
+++ b/calc.py
@@ -0,0 +1,2 @@
+def add(a, b):
+    return a + b

$ python commit_msg.py
Генерую повідомлення...
feat(calc): add basic addition function
```

Рядок «Генерую повідомлення...» показує, що запит надіслано. Саме повідомлення з'являється потоком у міру генерації. Інші приклади результатів:

| Зміна | Результат |
|---|---|
| виправлено вихід за межі при поділі на сторінки | `fix(paginate): correct page size calculation` |
| лише відступи й пробіли | `style(parser): fix indentation and formatting` |
| оновлено версію бібліотеки в `package.json` | `build(express): update to version 4.19.2` |
| цикл замінено на `sum`, функцію винесено окремо | `refactor(report): replace loop with sum and extract calc_total function` |

## Параметри генерації

| Параметр | Значення | Чому |
|---|---|---|
| Модель | qwen3:4b-instruct-2507-q4_K_M | Instruct-модель без режиму міркування: для короткого повідомлення міркування не потрібне, воно лише додає затримку. Вміщається у 6 GB VRAM повністю (≈ 3.5 GB), швидкість ≈ 61 tokens/s. |
| temperature | 0.2 | Потрібен стабільний формат і точний зміст, а не творчість. Не 0, щоб при повторному запуску можна було отримати трохи інше формулювання. |
| max_tokens | 60 | Обовʼязковий ліміт. Рядок до 72 символів це приблизно 25 токенів, решта запас. Ліміт захищає від зациклення моделі. |
| Контекст | 4096 токенів (значення Ollama за замовчуванням для цієї відеокарти) | Системний промпт займає близько 350 токенів. Тому diff обрізається до 6000 символів (приблизно 2000 токенів), щоб усе вмістилося в контекст. |
| timeout | 60 с | Відповідь у 25 токенів триває менше секунди. 60 с залишає запас для завантаження моделі в памʼять при першому запуску. |

## Повідомлення про помилки

- Сервер не запущено: «не вдалося підключитися до сервера».
- Модель не завантажено: «модель ... не знайдена», з командою `ollama pull`.
- Таймаут: «сервер не відповів за N с».
- Порожній diff: «Немає змін».
- Відповідь не у форматі Conventional Commits або порожня: попередження чи повідомлення про помилку.
- Diff довший за 6000 символів: попередження, що повідомлення складене лише за початком diff.

## Обмеження

Мала модель інколи плутає тип коміту або scope і описує лише видиму частину великого diff, тож повідомлення варто перечитати перед `git commit`.
