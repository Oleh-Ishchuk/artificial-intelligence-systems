# Питай по моїх файлах (рівень 2, RAG на локальних моделях)

Веб-сторінка: завантажуєте лекції, конспекти чи підручники (`pdf`, `docx`, `pptx`, `txt`, `md`), ставите питання, а застосунок знаходить у файлах потрібні фрагменти й відповідає лише за ними, із посиланням на файл і сторінку. Якщо відповіді в матеріалах немає, він так і каже.

## Запуск (Windows, PowerShell)

1. Встановіть [Python 3.10+](https://www.python.org/downloads/) (з галочкою «Add python.exe to PATH») та [Ollama](https://ollama.com/download).

2. Завантажте дві моделі: для відповідей і для пошуку по фрагментах:

```powershell
ollama pull qwen2.5:7b-instruct
ollama pull bge-m3
```

3. Перейдіть у папку рішення й поставте залежності:

```powershell
cd mkr1\solution
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

4. Запустіть застосунок:

```powershell
.venv\Scripts\python app.py
```

5. Відкрийте <http://127.0.0.1:5000>. Індикатор у лівому нижньому куті має стати зеленим. Натисніть «Новий чат» і додайте файли скріпкою біля поля питання або перетягніть їх у вікно чату: вони з'являться праворуч у списку файлів чату, і питання ставляться лише по них. Історія питань зберігається окремо для кожного чату. Якщо додати файли з головного екрана, чат створюється автоматично.

Linux/macOS: замість `.venv\Scripts\python` використовуйте `.venv/bin/python`.

Старий формат `.doc` не підтримується: збережіть файл у Word як `.docx`.

## Метрики використання

Після роботи з застосунком (користувач ставить оцінки «Так/Ні» під відповідями):

```powershell
.venv\Scripts\python stats.py --baseline-min 1.17 --out ..\evidence\stats_output.md
```

`--baseline-min` це середній час ручного пошуку відповіді (хв), виміряний «до»; `--out` зберігає таблицю у файл (у PowerShell `>` дає UTF-16).

## Перевірка без моделей

Тестовий режим підставляє прості заглушки замість Ollama, щоб переглянути інтерфейс:

```powershell
$env:LLM_BACKEND="mock"
.venv\Scripts\python app.py
```

## Налаштування (змінні середовища)

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `OLLAMA_MODEL` | `qwen2.5:7b-instruct` | модель для відповідей |
| `EMBED_MODEL` | `bge-m3` | модель для пошуку по фрагментах |
| `EMBED_ON_CPU` | `1` | embeddings на процесорі, щоб не займати відеопам'ять; `0` = на GPU |
| `OLLAMA_NUM_CTX` | `4096` | контекст чату |
| `LEX_WEIGHT` | `0.15` | вага збігу слів питання з текстом фрагмента при впорядкуванні результатів пошуку (0 = лише embeddings) |
| `OLLAMA_NUM_PREDICT` | `512` | максимум токенів у відповіді |
| `OLLAMA_KEEP_ALIVE` | `30m` | скільки моделі лишаються в пам'яті після запиту (менше перезавантажень) |
| `EMBED_WORKERS` | `2` | скільки пачок фрагментів рахувати паралельно під час індексації |
| `EMBED_INDEX_ON_GPU` | `0` | `1` = індексацію рахувати на GPU, а питання на CPU: файли завантажуються швидше, але потрібна відеопам'ять |
| `WARMUP` | `1` | завантажити моделі у пам'ять при старті, щоб перше питання не чекало |
| `CHUNK_CHARS` / `CHUNK_OVERLAP` | `900` / `150` | розмір фрагмента і перекриття, символів |
| `TOP_K` | `4` | скільки фрагментів передається моделі |
| `MIN_SCORE` | `0.2` | якщо найближчий фрагмент менш схожий, модель не викликається |
| `OLLAMA_URL` | `http://localhost:11434` | адреса Ollama |
| `DATA_DIR` | `solution/data` | де зберігається індекс |
| `LOG_DIR` | `../evidence/logs` | куди пишеться журнал `rag.jsonl` |

## Як це працює

1. **Індексація.** Текст файлу ріжеться на фрагменти по ≈900 символів (кожна сторінка чи слайд окремо, тому номер сторінки точний), для кожного фрагмента `bge-m3` рахує вектор. Індекс зберігається на диску (`data/`), повторне завантаження незміненого файлу пропускається.
2. **Пошук.** Питання перетворюється на вектор, і знаходяться `TOP_K` найближчих фрагментів за косинусною схожістю (`numpy`).
3. **Відповідь.** `qwen2.5:7b-instruct` отримує лише ці фрагменти та інструкцію відповідати тільки за ними; текст з'являється поступово. Модель спершу наводить дослівну цитату, а застосунок перевіряє, що вона справді є у файлі: це відображається як «Підтверджено цитатою». Результат у JSON: `found`, `answer`, номери використаних фрагментів. Якщо відповіді немає, повертається `found=false`.
4. **Журнал.** Кожне індексування, питання та оцінка пишуться в `evidence/logs/rag.jsonl`.

```
  stats.py        метрики з журналу
  templates/index.html
  static/css/style.css
  static/js/       модулі інтерфейсу: main, core, chats, sidebar, upload, home, chat, composer, icons
```
